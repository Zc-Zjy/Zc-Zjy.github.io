Springboot中查看耗时的几种方式

十七2025-10-102025-10-10


一、System.currentTimeMillis()

这是最原始但最直接的方式，适用于快速验证某段代码的执行时间。

优点：

  • 无需引入任何依赖；
  • 简单直观，适合临时调试。

缺点：

  • 代码侵入性强；
  • 多处使用时重复代码多；
  • 精度受系统时钟影响（可能受NTP调整干扰）。

适用场景：

  • 本地开发调试；
  • 快速验证某段逻辑耗时。

注意：
该方法基于系统时间，不适用于高精度计时。推荐使用System.nanoTime()替代（见后文补充）。



二、使用StopWatch工具类

Spring提供了org.springframework.util.StopWatch类，支持分段计时和格式化输出，适合需要统计多个子任务耗时的场景。

优点：

  • 支持多任务分段计时；
  • 输出美观，便于分析；
  • 可命名任务，提升可读性。

缺点：

  • 仍需手动插入代码；
  • 不适用于自动化监控。

适用场景：

  • 需要分析多个步骤耗时占比的复杂流程。


三、使用AOP切面+自定义注解（推荐）

通过面向切面编程（AOP），可以实现对指定方法的无侵入式耗时监控。

（2）远程调用（RPC/HTTP）；
（3）数据库查询；
（4）复杂计算逻辑。

（2）微服务架构下的统一指标体系。



五、使用Java8的Instant与Duration

Java 8 引入了新的时间 API，更加安全和易用。

优点：

  • 使用现代时间 API，语义清晰；
  • 线程安全，避免旧 Date 的坑。

缺点：

  • 仍需手动编码；
  • 性能略低于 nanoTime。

适用场景：

  • 偏好 Java 8+ 新特性的项目。


六、异步方法耗时统计CompletableFuture

对于异步任务，可通过回调机制统计耗时。

优点：

  • 适用于非阻塞场景；
  • 可结合线程池监控。

适用场景：

  • 异步消息处理；
  • 批量任务调度。
